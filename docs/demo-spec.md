# 브레인빌리지 데모 기획 스펙 v1.0

> 2026-08-22 기획 검토 회차에서 확정. 구현 착수는 디자인 파일 수령 후.

## 1. 개요

고령자 대상 **동작 기반 인지훈련** 기능성 콘텐츠. 마을에서 미니게임을 골라 플레이하며 인지 훈련을 수행한다.

| 항목 | 내용 |
|---|---|
| 플랫폼 | 웹 (Vite + React + TypeScript) |
| 동작 인식 | MediaPipe Tasks `PoseLandmarker` |
| 인원 | 2인 협동 (경쟁 없음) |
| 운영 환경 | 행사 부스, 진행요원 상주 |
| 데모 범위 | 메인 → 마을 → 튜토리얼 → 오락가락 운동회 1종 |

## 2. 화면 플로우

```
메인 (로고 + 시작)
  └─ 마을 (게임 선택, 아이콘 4~5개 / 미구현은 "준비중")
       └─ 튜토리얼 (게임별 상이)
            ├─ ① 아바타 선택 (할아버지 / 할머니, 참가자 직접)
            ├─ ② 위치 잡기 (카메라 강제 ON, 좌우 분할선 안내)
            ├─ ③ 캘리브레이션 (양손 최대한 들기 3초)
            └─ ④ 무채점 연습 3~5구령
                 └─ 오락가락 운동회 본 플레이
                      └─ 결과 (팀 점수 + JSON 다운로드)
```

- 마을 화면 선택은 **마우스/터치** (진행요원 상주 전제)
- 아이콘 호버 시 확대 + 게임 설명 노출

## 3. 오락가락 운동회

### 3.1 기본 구조

- 좌측 **1P**, 우측 **2P**
- 시작 시 청기/백기 역할 **무작위 배분**
- **2라운드 × 10구령 = 총 20구령**, 라운드 사이 역할 교체 안내 구간
- 구령 시퀀스는 **고정** (난이도 커브 보장 + 참가자 간 비교 가능)
- 지시 후에는 항상 손을 내림 → "내려" 계열 구령은 없음

### 3.2 사이클 타이밍

```
[구령 발화: 오디오 실제 길이 1.0~3.0s] → [반응 창: 2.0s] → [피드백: 1.0s]
```

- 반응 창은 **발화 종료 시점**에 열림
- 라운드 소요 ≈ 50~60초 / 총 플레이 ≈ 2분 / 튜토리얼 포함 4~5분
- 발화 길이는 녹음 파일 실측값을 상수로 고정

### 3.3 난이도 레벨

| 레벨 | 형태 | 예시 |
|---|---|---|
| L1 | 단일 지시 | `청기 들어!` |
| L2 | 좌우 지정 | `백기 왼손 들어!` / `둘다 오른손 들어!` |
| L3 | 페이크 (물음표) | `청기 들어?` |
| L4 | 복합 (부정 결합) | `청기 들지말고 백기 들어!` |

배분: **L1 7 · L2 6 · L3 4 · L4 3**

### 3.4 확정 구령 시퀀스

**1라운드** — 1P = 청기, 2P = 백기

| # | Lv | 구령 | 1P 기대동작 | 2P 기대동작 |
|---|---|---|---|---|
| 1 | L1 | 청기 들어! | 양손 | — |
| 2 | L1 | 백기 들어! | — | 양손 |
| 3 | L1 | 백기 들어! | — | 양손 |
| 4 | L1 | 청기 들어! | 양손 | — |
| 5 | L1 | 둘다 들어! | 양손 | 양손 |
| 6 | L2 | 청기 왼손 들어! | 왼손 | — |
| 7 | L2 | 백기 오른손 들어! | — | 오른손 |
| 8 | L3 | 청기 들어**?** | — | — |
| 9 | L2 | 둘다 왼손 들어! | 왼손 | 왼손 |
| 10 | L3 | 백기 오른손 들어**?** | — | — |

**2라운드** — 역할 교체: 1P = 백기, 2P = 청기

| # | Lv | 구령 | 1P 기대동작 | 2P 기대동작 |
|---|---|---|---|---|
| 11 | L1 | 백기 들어! | 양손 | — |
| 12 | L1 | 청기 들어! | — | 양손 |
| 13 | L2 | 둘다 오른손 들어! | 오른손 | 오른손 |
| 14 | L2 | 청기 왼손 들어! | — | 왼손 |
| 15 | L2 | 백기 오른손 들어! | 오른손 | — |
| 16 | L3 | 둘다 들어**?** | — | — |
| 17 | L3 | 백기 왼손 들어**?** | — | — |
| 18 | L4 | 청기 들지말고 백기 들어! | 양손 | — |
| 19 | L4 | 백기 들지말고 청기 왼손 들어! | — | 왼손 |
| 20 | L4 | 왼손 들지말고 둘다 오른손 들어! | 오른손 | 오른손 |

**균형 검증**
- 1P 반응 요구: 10회 / 2P 반응 요구: 10회 (동일)
- 대상 분포: 청기 지정 7 · 백기 지정 8 · 둘다 5
- 무반응이 정답인 문항: 4회 (L3 페이크 전체)

11~12번에 L1을 다시 배치한 이유: 역할 교체 직후 이전 규칙 잔상(perseveration)으로 무조건 틀리는 것을 막고 2라운드 지표의 타당성을 확보한다.

## 4. 판정

### 4.1 동작 판정

| 항목 | 규칙 |
|---|---|
| 좌우 기준 | **사용자 신체 기준** (내 왼손), 화면은 거울 모드 |
| 임계선 | 캘리브레이션으로 측정한 **개인 최대 손목 높이의 70~80%** |
| 유지 시간 | 0.2~0.3초 (단발 노이즈 방지) |
| 2인 인식 | 프레임을 **좌/우로 분할**해 각 영역에 단일 포즈 추정 |

좌우 분할 방식을 택한 이유: `numPoses: 2`는 두 사람이 겹치거나 한 명이 프레임을 벗어날 때 플레이어 ID가 스왑되어 채점 전체가 무효화될 수 있다. 분할 방식은 플레이어 귀속이 물리적으로 보장되고, ROI가 작아 추론 비용 증가도 상쇄된다.

### 4.2 채점

| 구분 | 규칙 |
|---|---|
| 플레이어별 판정 | 기대동작(`NONE` / `양손` / `왼손` / `오른손`) 대비 정·오 |
| 비호명 플레이어 | **참으면 정답으로 카운트** (억제 통제가 핵심 과제) |
| 양손 요구에 한 손만 | 오답 (로그에는 `부분수행`으로 별도 기록) |
| 조급반응 (발화 종료 전 반응) | **오반응** |
| 팀 점수 | 2명 정답 **5점** / 1명 **3점** / 0명 **1점** |
| 만점 | 20구령 × 5점 = **100점** (최저 20점) |
| 화면 표시 | **팀 통합 점수 1개만** — 개인 점수는 노출하지 않음 |

최저점 20점은 의도된 격려 설계다. 고령자 참가 자존감 유지 및 부스 상황을 고려한 결정.

### 4.3 로그 전용 지표

구령마다 다음을 기록한다.

```
{
  구령ID, 레벨, 대상, 기대동작(1P/2P),
  플레이어별 정오,
  반응속도(ms)   // 발화 종료 → 손목 임계선 통과
  오류유형        // 누락(무반응) | 오작동 | 오손 | 부분수행 | 조급반응
}
```

- 반응속도는 반응이 정답인 문항에서만 정의 (무반응 정답 문항은 집계 제외)
- 결과 화면에 **JSON 다운로드** 버튼 제공

## 5. 아바타

### 5.1 구성

레이어 구조: **아바타 바디 레이어** + 그 위에 **표정 레이어**

| 레이어 | 변형 | 장수 |
|---|---|---|
| 바디 | 2 성별(할아버지·할머니) × 2 깃발색(청·백) × 4 포즈 | **16** |
| 표정 | 5종 (성별 공유) | **5** |

- 포즈 4종: `기본` / `양손들기` / `왼손들기` / `오른손들기`
- 표정 5종: `기본` / `웃음(성공)` / `왼쪽 째려보기` / `오른쪽 째려보기` / `울기`
- 깃발: **양손에 자기 색 깃발 1개씩**. `왼손들기`는 왼손 깃발만 올라감
- 성별은 튜토리얼에서 참가자가 직접 선택

### 5.2 표정 매핑

| 상황 | 1P (좌) | 2P (우) |
|---|---|---|
| 대기 / 구령 재생 중 | 기본 | 기본 |
| 둘 다 정답 | 웃음 | 웃음 |
| 나만 정답 (파트너 오답) | **오른쪽 째려보기** | **왼쪽 째려보기** |
| 나만 오답 (파트너 정답) | 울기 | 울기 |
| 둘 다 오답 | 울기 | 울기 |

째려보기 방향 = 항상 파트너가 있는 쪽. 어느 성별이 1P가 될지 모르므로 좌우 2종이 모두 필요하다.

### 5.3 프로덕션 제약

1. **얼굴 앵커 고정** — 4개 포즈 모두 머리 위치·크기를 동일하게 유지할 것. 포즈별로 몸이 기울면 표정 레이어가 어긋난다. (포즈별로 달리 그릴 경우 포즈별 얼굴 앵커 좌표를 별도 전달)
2. **표정 레이어는 눈·입 파츠만** — 성별 공유이므로 머리 윤곽·머리카락·주름은 바디 레이어에 포함되어야 하고, 두 성별의 눈·입 위치가 동일해야 한다.

## 6. 연출 / 접근성

- **웹캠 화면**: 아바타가 메인 피드백. 카메라 화면은 별도 배치하되 **ON/OFF 토글**. 단 튜토리얼 위치 잡기·캘리브레이션 구간은 **강제 ON**
- 카메라를 끈 참가자도 "얼마나 들어야 하는지" 알 수 있도록, 아바타 옆에 **도달 게이지/링** 별도 표시
- **구령 제시**: 실제 사람 녹음 + 대형 텍스트 + 아이콘 동시 제시
- **페이크 구령**: 억양만으로는 난청 참가자에게 불공정하므로, 화면에 **물음표를 크게** + 지시문 박스 색/테두리 차별화
- **청/백 색상**: 백내장·색약 고려해 명도 차 + 도형/패턴 병행
- **실패 피드백**: 빨간 X, 실패 효과음 등 부정적 연출 배제. 표정으로만 표현하고 색상·사운드는 중립 톤

## 7. 구현 노트

React 렌더 사이클과 게임 루프를 분리해야 한다. 반응속도를 ms 단위로 측정하는 게임이므로:

- MediaPipe 루프 + 판정 로직은 `requestAnimationFrame` + `useRef`(또는 외부 스토어)에서 실행. 프레임마다 `setState` 하면 렌더가 폭주한다
- 타이머는 `setTimeout` 누적 대신 **rAF 타임스탬프 기준**으로 계산
- UI로 올리는 state는 throttle: 현재 구령 / 남은 시간(100ms 단위) / 손 올림 여부(bool) 정도
- `PoseLandmarker`는 GPU delegate, 모델은 `lite`로 시작

## 9. 정식 버전 이관 항목

데모 범위에서 제외하고 정식 버전으로 미룬 것들.

- **협동 연출**: 동시성 보너스(둘 다 정답 + 반응 시간 차 0.5초 이내), 팀 콤보 게이지. 데모는 점수 합산만 유지
- 세션 데이터 **서버 전송** 및 누적 리포트 (데모는 로컬 JSON 다운로드)
- 미니게임 추가 (마을 아이콘 "준비중" 슬롯)
- 동작 기반 UI (자가 진행 환경 대응)
