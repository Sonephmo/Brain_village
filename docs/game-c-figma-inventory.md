# 영차마을 게임 C — Figma 기반 구현 기록

작업일: 2026-09-19. 게임명: **쿵떡쿵떡 떡방아**, 진입 버튼: **보름달 떡집**.

## 화면 흐름

마을의 보름달 떡집 → 위치 잡기 → 손 내려놓기 → 양팔 높이 보정 → 토끼 선택 → 동작 연습 → 연습 중 역할 교대 → 훈련 완료 → 암전 → 배경 연출 → UI 디졸브 → 카운트다운 → 1라운드 → 역할 교대 → 2라운드 → 완성 동작 → 결과.

- 1라운드는 1P가 떡 치기, 2P가 떡 정리를 맡는다. 2라운드에는 역할을 바꾼다.
- 연습에서는 방아찧기, 잼잼, 오른손, 왼손과 교대 후 동작을 안내한다. 성공하면 다음 단계로 이동하며 연습 점수는 없다.
- 두 라운드를 마치고 50점 이상이면 두 사람 모두 양팔을 머리 위로 드는 마무리 단계를 거친다. 50점 미만이면 결과로 이동한다.
- 다시하기는 같은 토끼로 연습 없이 본게임을 시작한다. 확인은 마을, 홈으로는 타이틀로 이동한다.
- 진행요원의 연습/마무리 건너뛰기는 점수를 주지 않는다. 마무리 건너뛰기는 수행 완료로 기록하지 않는다.
- 중단한 게임은 현재까지 판정을 마친 구령만 기록하며, 완주로 표시하지 않는다.

### 본게임 진입 및 결과 연출

| 단계 | 시간 / 동작 |
|---|---|
| 튜토리얼 종료 | 기존 화면을 검은색으로 0.8초 페이드 아웃 |
| 본게임 배경 등장 | 검은색에서 원본 배경으로 1초 페이드 인 |
| 배경 단독 | 흐림 0·보정 전 원본 밝기로 3초 유지 |
| 배경 보정 | 0.5초 동안 Figma 흐림 30·노출 −0.4로 전환 |
| UI 등장 | 나머지 UI를 0.6초 동안 디졸브 |
| 게임 시작 | UI 등장 완료 후 카운트다운, 이어서 시간·동작 판정 시작 |
| A·B·C 결과 공통 | 배경 이미지 로딩 완료부터 2초간 배경만 표시, 이후 UI 0.6초 디졸브 |

Figma 흐림 30은 디자인 도구가 반환한 CSS `blur(15px)`로 대응한다. 노출은 Figma의 보정된 이미지와 보정 전 원본을 겹쳐 전환하여 −0.4의 실제 색감을 유지한다. 초기 배경 원본까지 미리 읽고 시작한다. 디졸브 중 UI에는 `inert`와 입력 차단을 적용하여 보이지 않는 버튼이 눌리지 않는다. 재도전도 배경 연출부터 다시 시작한다. 운영체제의 동작 줄이기 설정에서는 페이드 시간을 줄이되 배경 단독 노출 시간은 유지한다.

사용자 정정에 따라 왼손 연습과 교대 후 잼잼 연습을 보완했고, 성별 선택 문구를 토끼 선택으로 바꿨다. 충돌·화냄·아파하기 등 재미 요소는 구현하지 않았다. 마무리용 양팔 들기 토끼 그림은 확보한 에셋에 없어 기본 토끼 그림과 동작 안내·진행 막대를 사용한다. 말풍선의 Figma 글꼴 을유1945는 로컬 파일이 없어 바탕 계열로 대체했다.

## 동작 규칙과 현재 설정

사용자가 확정한 규칙:

- 떡 치기: 양손을 **들었다 내리는 전체 동작**을 해야 1회 인정한다. 들기만 하면 인정하지 않는다.
- 떡 정리: **왼손 들기**, **오른손 들기**, **잼잼 3회**.
- 완성 동작: **두 사람 모두 양팔을 머리 위로 들기**.

흐름 검증을 위해 적용한 설정은 `src/game/gameC.ts`의 `GAME_C_RULES`와 구령 배열에 모아두었다. 현장 실측으로 확정한 난이도는 아니다.

| 항목 | 현재 값 |
|---|---|
| 채점 구령 | 20개, 라운드마다 각 사람 5개 |
| 구령당 시간 | 반응 2초 + 피드백 1초 |
| 본게임 시간 | 약 30초 × 2라운드; 교대 4초 별도 |
| 점수 | 성공 구령당 5점, 최대 100점 |
| 완성 기준 | 두 라운드 완주 + 50점 이상 |
| 상태 유지 | 120ms 이상 유지한 입력 사용 |
| 잼잼 | 양손 펴기 → 양손 쥐기 → 다시 펴기 3회 |
| 완성 동작 유지 | 두 사람이 동시에 머리 위로 1초 |
| 개인 결과의 떡 표시 | 성공 2회당 1개, 총 5개 |

매 구령은 손을 내린 상태(잼잼은 편 상태)에서 새로 시작해야 한다. 가려짐이나 추적 끊김을 손 내림으로 계산하지 않는다. 완성 동작도 두 사람이 먼저 팔을 내린 것이 확인되어야 시작한다. 올바르게 완료한 구령은 첫 유효 반응 시간과 완료 시간을 함께 기록한다. 미완료 구령은 움직임이 있었으면 `wrong`, 없으면 `missed`로 기록한다.

- 수정된 마을 지도에서 병원 왼쪽의 달 간판 건물 **보름달 떡집**을 눌러 진입한다. Figma `313:2`(이전 레이어명 `Place_Pharmacy`)의 영역 `(560, 716, 337, 257)`에 게임 C를 연결했으며 임시 진입 버튼은 제거했다.
- 카메라를 쓸 수 없으면 키보드 모드다. 카메라가 켜져 있어도 게임 C의 **입력 안내 → 키보드로 전환**으로 선택할 수 있다.
- 1P: Q 왼손, W 오른손, E 잼잼. 2P: O 왼손, P 오른손, I 잼잼.
- 떡 치기는 양손 키를 함께 누른 뒤 놓는다. 잼잼은 E 또는 I를 눌렀다 놓기를 3번 한다. 각 상태는 약 0.2초 이상 유지한다.
- 완성 단계에서는 Q/W/O/P를 모두 함께 1초 이상 누른다.
- 1은 연습/마무리 건너뛰기, 2는 본게임 중 4초 안에 두 번 눌러 중단하기다.

## 검증 범위와 남은 연결

- TypeScript 검사, 프로덕션 빌드 및 동작 판정 회귀 테스트를 통과했다.
- 최신 연출은 브라우저에서 `fadeIn → backgroundHold → backgroundFocus → uiReveal → countdown` 순서, 배경 구간에서 UI 없음, 카운트다운까지 남은 시간 60 유지, 결과의 배경 단독 표시 및 UI 등장 완료를 확인했다. 결과 연출은 A·B·C가 동일한 `ResultReveal` 컴포넌트를 사용한다.
- 브라우저에서 토끼 선택, 모든 연습 종류, 연습 역할 교대, 본게임, 두 라운드 종료 및 50점 미만 결과, 연습 없는 재도전, 두 번 눌러 중단하기와 마을 복귀를 확인했다. 표시 중인 이미지 로딩 실패와 브라우저 오류 로그는 없었다.
- 회귀 테스트는 들기만 한 동작 배제, 들었다 내리기, 추적 끊김, 기존에 든 손, 잼잼 3회, 두 사람의 머리 위 마무리 동작, 짧은 잡음, 오동작/무반응 구분, 플레이어별 구령 균형, 중단 결과 평가를 검사한다.
- 테스트 브라우저에 카메라가 없어 실제 2인 신체·손가락 인식의 정확도와 지연은 검증하지 못했다. 특히 2초 안에 양손 잼잼 3회를 인식하는 난이도와 머리 위 임계선은 장비·사용자 실측이 필요하다.
- 게임 C용 녹음 안내 음성은 아직 없다. 현재는 화면 안내와 기존 카운트다운·휘슬을 사용한다.
- 게임 C 결과는 화면 및 JSON 다운로드까지 제공한다. 서버 전송은 아직 연결하지 않았다.
