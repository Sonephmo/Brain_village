### 개인별 보름달 점수

- 각 줄 위에 1P·2P를 표시하고 아래에 해당 플레이어의 달 다섯 개를 배치한다. 팀 합산 점수 대신 각 플레이어의 성공 기록을 사용하며, 역할 교대 이후에도 점수와 좌우 위치를 유지한다.
- 개인 최대 50점을 `0…1` 연속 파라미터로 변환한다. 달 하나는 10점이며, 성공 1회(5점)에는 반 개, 2회에는 한 개가 채워진다. 전체 개수로 반올림하지 않으므로 소수 점수도 부분 채움으로 표현할 수 있다.
- 원본 달 이미지의 색상 레이어를 아래에서 위로 드러내며, 점수 변경마다 0.8초 동안 부드럽게 보간한다. 빈 부분에는 흐린 회색 달을 유지한다. 동작 줄이기 설정에서는 보간만 생략하고 부분 채움은 그대로 표시한다.
- 채점·팀 만점 100점·완성 기준 50점·결과 화면의 평가는 유지한다. 연습·실패·무반응에는 점수를 추가하지 않는다.

달 말풍선의 문구 넘침을 수정했다. 연습·본게임 모두 글자 크기 66px, 줄 높이 1.4를 사용하며, 달 안쪽의 500×260 영역에서 가로·세로 중앙 정렬한다. 문구는 유지하고 본게임의 96px 확대 규칙을 제거하여 가장 긴 오른쪽 뒤집기 안내까지 두 줄로 표시한다.

사용자 정정에 따라 왼손 연습과 교대 후 잼잼 연습을 보완했고, 성별 선택 문구를 토끼 선택으로 바꿨다. 충돌·화냄·아파하기 등 재미 요소는 구현하지 않았다. 마무리용 양팔 들기 토끼 그림은 확보한 에셋에 없어 기본 토끼 그림과 동작 안내·진행 막대를 사용한다. 말풍선의 Figma 글꼴 을유1945는 로컬 파일이 없어 바탕 계열로 대체했다.

## 동작 규칙과 현재 설정

사용자가 확정한 규칙:

- 떡 치기: 양손을 **들었다 내리는 전체 동작**을 해야 1회 인정한다. 들기만 하면 인정하지 않는다.
- 떡 정리: **왼손 들기**, **오른손 들기**, **잼잼 3회**.
- 완성 동작: **두 사람 모두 양팔을 머리 위로 들기**.

흐름 검증을 위해 적용한 설정은 `src/game/gameC.ts`의 `GAME_C_RULES`와 구령 배열에 모아두었다. 현장 실측으로 확정한 난이도는 아니다.

| 항목 | 현재 값 |
|---|---|
| 채점 구령 | 20개, 라운드마다 각 사람 5개 |
| 구령당 시간 | 반응 3초 + 피드백 1초 = 4초 |
| 본게임 시간 | 약 40초 × 2라운드 = 80초; 교대 4초 별도 |
| 점수 | 성공 구령당 5점, 최대 100점 |
| 완성 기준 | 두 라운드 완주 + 50점 이상 |
| 상태 유지 | 120ms 이상 유지한 입력 사용 |
| 잼잼 | 양손 펴기 → 양손 쥐기 → 다시 펴기 3회 |
| 완성 동작 유지 | 두 사람이 동시에 머리 위로 1초 |
| 개인 결과의 떡 표시 | 성공 2회당 1개, 총 5개 |

매 구령은 손을 내린 상태(잼잼은 편 상태)에서 새로 시작해야 한다. 가려짐이나 추적 끊김을 손 내림으로 계산하지 않는다. 완성 동작도 두 사람이 먼저 팔을 내린 것이 확인되어야 시작한다. 올바르게 완료한 구령은 첫 유효 반응 시간과 완료 시간을 함께 기록한다. 미완료 구령은 움직임이 있었으면 `wrong`, 없으면 `missed`로 기록한다.

구령당 4초 변경은 `flow-2` 규칙으로 기록한다. 화면의 시작 시간·남은 시간은 구령 수와 반응·피드백 설정에서 계산하여, 실제 판정 시간과 타이머 표시가 함께 변경되도록 했다.
브라우저에서도 여러 연속 구령의 수행 약 3초·피드백 약 1초, 구령 시작 간격 약 4초와 남은 시간 68 → 64 → 60 → 56 표시를 확인했다.

### 동작 이펙트

- 별: Figma `306:81`–`306:84`. 양손을 들었다 내리는 동작이 인정되는 순간 떡메 아래에서 재생한다. 올리는 동작만으로는 재생하지 않는다.
- 믹스: Figma `306:13`, `306:14`, `306:15`, `306:12`. 보조 역할의 왼손·오른손 들기가 인정되거나 잼잼 한 사이클을 마칠 때마다 떡 위에서 재생한다. 잼잼 구령은 3회 모두 완료해야 점수를 받는다.
- 각각 4프레임을 150ms씩 총 0.6초 재생한다. 연습·본게임·역할 교대 후에도 같은 규칙을 사용하며, 포즈 유지·추적 끊김·잘못된 동작에는 반복 재생하지 않는다. 새로운 동작은 처음 프레임부터 재생한다.
- 운영체제의 동작 줄이기 설정에서는 이펙트를 숨기고 기존 GOOD·횟수 표시를 유지한다.

### 토끼와 반죽 모션

`Game C Assets`(`288:164`)의 현재 원본과 로컬 파일을 대조했다. 반죽 번호는 `Dough_01`–`Dough_04`와 그대로 대응하며, 좌우 변형을 인위적으로 뒤집지 않는다.

- 떡메 토끼는 구령 종류와 무관하게 해당 플레이어의 양손 위치로 UP/DOWN을 표시한다. 피드백 중에도 손 위치를 계속 읽는다. 단순 DOWN 대기는 타격으로 판정하지 않으며, 새 구령의 대기 상태가 확인된 뒤 UP → DOWN을 완료해야 별·타격 반죽·성공 판정이 발생한다.
- 보조 토끼는 대기 시 Idle, 왼손·오른손 들기 또는 잼잼의 유효한 움직임이 감지되면 Squeeze_01 ↔ Squeeze_02를 150ms마다 번갈아 표시한다. 쥔 자세를 계속 유지하는 것만으로 반복을 연장하지 않는다.
- 떡메 반죽은 기본 04 → 유효한 내려치기에서 01 → 0.3초 뒤 04로 복귀한다.
- 보조 반죽은 기본 04에서 시작하며 수행 시 02 → 04 → 03 → 04 → 02 순서로 150ms마다 반복한다. 연속 동작은 재생 위치를 유지한 채 반복을 연장한다.
- 사용자가 확인한 대로 판정 순간에 그림을 끊지 않고 짧은 모션을 마친 뒤 복귀한다. 보조 모션은 마지막 유효한 움직임 이후 0.75초 뒤 Idle·04로 돌아간다. 다음 구령·역할 교대·입력 방식 변경·추적 끊김에서는 즉시 기본 상태로 초기화한다.
- 모션은 점수나 동작 횟수에 영향을 주지 않는다. 동작 줄이기 설정에서는 보조 반복·반죽 모션을 생략하고 실제 손 위치에 따른 떡메 자세와 성공 표시를 유지한다.

## 검증 범위와 남은 연결

- TypeScript 검사, 프로덕션 빌드 및 동작 판정 회귀 테스트를 통과했다.
- 최신 연출은 브라우저에서 `fadeIn → backgroundHold → backgroundFocus → uiReveal → countdown` 순서, 배경 구간에서 UI 없음, 카운트다운까지 시작 시간 유지, 결과의 배경 단독 표시 및 UI 등장 완료를 확인했다. 결과 연출은 A·B·C가 동일한 `ResultReveal` 컴포넌트를 사용한다.
- 브라우저에서 토끼 선택, 모든 연습 종류, 연습 역할 교대, 본게임, 두 라운드 종료 및 50점 미만 결과, 연습 없는 재도전, 두 번 눌러 중단하기와 마을 복귀를 확인했다. 표시 중인 이미지 로딩 실패와 브라우저 오류 로그는 없었다.
- 회귀 테스트는 들기만 한 동작 배제, 들었다 내리기, 추적 끊김, 기존에 든 손, 잼잼 3회, 두 사람의 머리 위 마무리 동작, 짧은 잡음, 오동작/무반응 구분, 플레이어별 구령 균형, 중단 결과 평가를 검사한다.
- 이펙트 회귀 테스트는 내려친 순간 별 1회, 잼잼 각 사이클 및 왼손·오른손의 믹스 1회, 자세 유지·오동작·추적 끊김에서 이펙트가 발생하지 않는 것을 검사한다.
- 임시 브라우저 검증 화면에서 실제 `GameCEffect` 컴포넌트의 별·믹스 4프레임 크롭, 떡판 기준 위치, 순차 재생 후 사라짐, 이미지 로딩 성공을 확인했다. 검증용 화면은 제거했다.
- 모션 회귀 테스트는 DOWN 대기 미판정, 손 위치별 떡메 자세, 정확한 반죽 순서, 보조 1·2 반복, 유지 자세에서 Idle 복귀, 연속 입력 중 반복 유지, 모션 초기화와 동작 줄이기를 검사한다. 임시 브라우저 화면에서 실제 `GameCScreen`에 제어된 신체·손 입력을 공급하여 UP → DOWN 판정, 01 → 04 복귀, 보조 반죽 전체 순서, 잼잼 3회 성공까지 확인했다. 실제 카메라 정확도 검증과는 구분한다.
- 테스트 브라우저에 카메라가 없어 실제 2인 신체·손가락 인식의 정확도와 지연은 검증하지 못했다. 특히 3초 안에 양손 잼잼 3회를 인식하는 난이도와 머리 위 임계선은 장비·사용자 실측이 필요하다.
- 게임 C용 녹음 안내 음성은 아직 없다. 현재는 화면 안내와 기존 카운트다운·휘슬을 사용한다.
- 게임 C 결과는 화면 및 JSON 다운로드까지 제공한다. 서버 전송은 아직 연결하지 않았다.

## 변경 지점

- `src/game/gameC.ts`: 구령, 규칙, 동작 판정, 결과 형식, 토끼·반죽 모션 시계.
- `src/game/gameCGrip.ts`: 수행자의 반쪽 영상에서 양손 펴기/주먹 인식.
- `src/game/gameCAssets.ts`, `src/components/GameCRabbit.tsx`, `GameCEffect.tsx`: 로컬 에셋, 시트 크롭 및 동작 이펙트.
- `src/screens/GameCScreen.tsx`, `GameCResultScreen.tsx`, `src/game-c.css`: 게임·결과 화면.
- `src/App.tsx`, `VillageScreen.tsx`, `TutorialScreen.tsx`: 진입, 준비, 토끼 선택, 재도전 연결.
- `src/game/pose.ts`: C용 손목 추적 상태, 높이 및 머리 위 판정 표본 제공.
- `src/components/ResultReveal.tsx`: 모든 게임의 결과 배경 대기·UI 디졸브·입력 활성화.
- `src/components/GameTimer.tsx`, `src/styles.css`: A·B·C 공통 타이머 디자인. 숫자 외곽선·그림자와 그라데이션 채움을 분리하여 투명 글자에 흰 그림자가 겹치지 않게 했다. A의 소수점·B/C의 정수 표시는 유지하며, A 구령과 B 점수·안내 간격을 확보했다.
- `src/components/GameCMoonScore.tsx`: 좌우 개인별 보름달 점수와 연속 부분 채움. `ricePlayerStats`의 실제 개인 점수·최대 점수를 사용한다.

개인 점수 변경 검증: 타입 검사·프로덕션 빌드·동작 및 점수 회귀 테스트를 통과했다. 브라우저에서 5점의 반달, 25점의 두 개 반, 50점의 다섯 개 채움과 0.8초 구간의 연속 보간을 확인했다. 실제 게임 컴포넌트에 제어된 1P 성공 입력을 공급해 1P만 득점하고, 역할 교대 이후에도 동일한 위치에서 25점 → 40점으로 누적되는 것을 확인했다. 임시 검증 화면은 제거했다.
