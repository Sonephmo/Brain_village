## 3. 미완성 기능과 기획 확인 사항

- **B·C 서버 전송 없음.** 현재 둘은 화면 결과와 JSON 출력 경로만 있다. A와 동일하게 기관/참가자별 누적 리포트를 기대한다면 추가 구현이 필요하다.
- **B의 규칙은 `draft-1`.** 연습은 5회, 본게임은 과제당 2회다. 본게임에서는 횟수 설명이 명확하지 않다. 실제 참가자에게 안내할 목표 횟수와 정지 규칙을 확정해야 한다.
- **B 중단 결과는 완료한 이벤트 수로 평가.** 초반 한 이벤트만 성공하고 중단해도 개인 성공률은 100%, 불꽃 5개가 될 수 있다. 화면에는 중단 기준임을 표시하지만 완주 평가와 비교하면 혼동될 수 있다. 정책 결정이 필요하다.
- **C 전용 안내 음성 없음.** 현재 화면 문구와 공통 효과음 중심이다. B도 과제별 안내 음성이 연결되어 있지 않다. 고령 참가자의 시선 이동·읽기 속도를 고려한 음성 보완을 권장한다.
- **C의 3초 잼잼 3회는 현장 검증 필요.** 정확한 두 손의 펴기→쥐기→펴기 인식, 인식 불명 상태, 수행자의 피로와 속도를 실제 환경에서 확인해야 한다. 코드 테스트 통과로 대체할 수 없다.
- **내보내기 식별 정보 부족.** B/C JSON에는 기관·참가자 코드와 공통 세션 ID가 없다. 파일 여러 개를 모아 개인별 경과를 분석하기 어렵다.
- **기록 시각의 의미 불일치.** A의 JSON `시작시각`은 `src/game/logging.ts:21`에서 다운로드 시점에 생성된다. `telemetry.ts:242`의 `onset_ts`도 구령 시작이 아니라 판정 완료 때 생성한 시각이다. 실제 시작 시각을 잡아 전달해야 한다.
- **화면·입력의 확장 구조.** 게임 종류를 `App`, 마을, 공통 튜토리얼 등 여러 곳에서 문자열 분기로 관리한다. 네 번째 게임을 넣기 전에 게임별 이름·장소·준비 단계·화면·결과·기록 방식을 등록하는 공통 정의를 두면 누락을 줄일 수 있다. 리팩터링 자체가 현재 결함은 아니다.
