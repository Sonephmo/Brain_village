# 잼잼 인식 수정 및 확인 — 2026-09-30

사용자 보고: 팔 올리기·내리기는 되지만 잼잼은 인식되지 않는다. 실제 사용자 카메라에서의 해결 여부는 아직 확인 대기 중이다.

추가 보고에 따라 청기백기의 좌우 구분을 게임 3·4에도 공통으로 적용했다. 장보기의 전체 화면 손목 배정을 참가자별 절반 인식으로 교체했고, 떡방아의 역할별 추적 모델도 분리했다. [추가 검토와 검증 범위](./player-routing-review.md)를 참고한다.

## 코드에서 재현한 문제

1. 떡방아는 두 손이 모두 `Open_Palm` 또는 모두 `Closed_Fist`로 분류되지 않으면 `unknown`을 반환했다. 한 손이 먼저 닫히거나 `None`이 나오는 정상적인 중간 자세도 추적 손실로 처리해 진행 중이던 동작을 초기화했다.
2. 장보기와 떡방아 모두 손 모델에서 손가락을 인식한 뒤에도 별도 신체 모델의 양쪽 손목 신뢰도가 낮으면 입력을 버렸다. 앞으로 뻗은 손이 손가락 모델에는 보이지만 신체 모델의 손목이 가려지는 경우를 화면 테스트로 재현했다.
3. 떡방아는 화면을 처음 열 때 카메라가 아직 준비되지 않았으면 손 모델을 시작하지 않았고, 나중에 준비돼도 다시 초기화하지 않았다.

## 수정

- 공통 `handGrip.ts`에서 손 관절을 검증한다. 확신도가 충분한 기존 펼침·주먹 분류를 유지하되, 해당 이름이 없을 때는 21개 손 관절과 손가락 길이 대비 굽힘으로 판정한다. 세계 좌표가 있으면 이를 사용해 손 회전과 크기에 따른 영향을 줄인다.
- 두 손이 서로 다른 상태이거나 움직이는 도중이면 `closing`, 손이 실제로 누락되거나 좌표가 유효하지 않으면 `unknown`으로 구분한다.
- 손가락 입력에는 신체 모델의 손목 신뢰도를 중복 요구하지 않는다. 참가자 존재 확인, 두 손 확인, 새로 펴기, 유지 시간, 추적 손실 시 미완성 동작 폐기 규칙은 유지한다.
- 떡방아의 늦은 초기화와 재시도·모델 재사용을 처리했다. 연속 추론 오류는 조용히 숨기지 않고 상태에 남긴다.
- 메뉴 주먹 선택도 같은 손 판정을 사용한다. 기존 1초 유지와 손을 다시 펴야 재선택할 수 있는 조건은 유지한다.
- 실제 카메라 점검 페이지: `/docs/hand-recognition/`. 카메라는 사용자가 시작 버튼을 눌렀을 때만 열린다. 사용자 영상·관절은 저장하거나 전송하지 않는다.

## 검증

- 브라우저에서 프로젝트에 포함된 실제 MediaPipe 모델을 GPU 설정으로 실행했다. 주먹 사진 1개 손, 편 손 사진 2개 손을 검출했고, 제스처 이름을 제외한 관절 판정도 모두 통과했다. 결과는 `model-report.json`에 저장했다. 이 파일은 공개 샘플 사진의 관절이며 사용자 카메라 자료가 아니다.
- 손 판정 5개 회귀 그룹: 실제 모델 관절의 회전·확대, `None` 분류, 중간 자세, 3회 주무르기, 두 참가자의 담기, 동영상 정지, 한 손 누락, 모델 재사용과 오류, 메뉴 주먹 유지·중복 방지.
- 화면·음성 테스트는 20개 그룹으로 확장했다. 늦은 카메라 준비, 신체 모델 손목 누락, 참가자 부재를 실제 화면 로직에 입력해 확인했다. 기존 공통 11개 그룹, 떡방아 동작 테스트, 장보기 9개 그룹도 통과했다.
- 타입 검사, 빌드, 변경 파일 형식 검사 통과. 게임 에셋 누락 0건.
- 실시간 카메라에서 사용자 손과 조명·거리 조건까지 검증한 것은 아니다. 점검 페이지에서 펼침/쥠 표시와 횟수 증가를 확인해야 한다.
