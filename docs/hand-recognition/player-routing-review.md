# 게임 3·4 플레이어 배정 검토 — 2026-09-30

사용자 보고: 잼잼 인식이 여전히 불안정하다. 청기백기의 플레이어 구분을 기준으로 떡방아와 장보기를 검토했다. 아래 수정은 코드 경로와 회귀 검사로 확인했으며, 수정 후 사용자 카메라의 개선 정도는 아직 확인하지 않았다.

## 확인한 차이

| 항목 | 청기백기 | 기존 떡방아 | 기존 장보기 |
|---|---|---|---|
| 화면 배정 | 원본 오른쪽 절반 = 1P, 왼쪽 절반 = 2P | 같은 절반 배정 | 전체 화면에서 손 4개 검출 후 손목 x로 배정 |
| 추적 모델 | 참가자마다 별도 Pose 모델 | 한 Gesture 모델에 현재 참가자의 절반을 번갈아 전달 | 한 Gesture 모델에서 두 참가자의 손을 함께 추적 |
| 중앙 부근 | 각 절반 안에서 검출 | 각 절반 안에서 검출 | 중앙 ±4% 손목을 제외하여 양손 쌍이 누락될 수 있음 |
| 손 입력 해상도 | 몸 기준 높이 480 이하 | 높이 480으로 축소 | 전체 화면 높이 720 이하 |

떡방아의 좌우 배정 방향 자체는 청기백기와 같았다. 장보기는 중앙 제외 조건 때문에 실제 검출된 손도 입력에서 빠질 수 있었다. 떡방아의 같은 VIDEO 모델을 서로 다른 참가자의 화면에 번갈아 사용하는 방식은 역할 변경 때 추적 기록을 섞을 여지가 있다. 이 기록 혼선이 실제 사용자 증상의 원인이었는지는 현장 확인이 필요하다.

## 반영한 변경

- `playerFrame.ts`: 청기백기의 기존 좌우 절반 좌표를 공통 함수로 옮겼다. Pose와 손 모델이 같은 원본 영역을 사용한다.
- `playerGrip.ts`: 각 참가자의 절반에 손 2개 모델을 따로 사용한다. 떡방아와 장보기는 이 두 모델을 공유한다. 참가자별 영상 시간·손 상태·추론 시간·오류 횟수도 따로 관리한다.
- 떡방아 손 입력은 원본 비율을 보존하며 높이 최대 720으로 유지한다. 원본 영상보다 확대하지 않는다. 역할 교대 때 미완성 손 입력을 폐기하고 모델 간 참가자 배정을 유지한다.
- 장보기의 전체 화면 손목 위치 분류와 중앙 ±4% 제외 조건을 제거했다. 신체 존재 검사로 화면 입력을 거를 때 손 모델의 캐시를 변경하지 않도록 결과를 복사한다.
- 손 모델의 첫 추론을 준비 단계에서 수행한다. 초기화 대기 중에는 떡방아 잼잼 응답 시간을 소비하거나 장보기 카운트다운을 진행하지 않는다. 장보기의 초기화 지연도 게임 중 멈춤으로 처리하지 않는다.
- 점검 화면에서 참가자별 몸 존재, 손 개수, 손 상태, 처리 시간, 입력 해상도를 확인할 수 있다.

게임 규칙은 유지했다. 떡방아는 편 손→쥔 손→편 손 3회, 장보기는 양손을 쥐는 순간 1회이며 다시 펴야 재입력된다. 실제 손 누락·정지 영상·참가자 부재는 성공으로 인정하지 않는다. 양손을 자기 화면 절반 안에 두는 청기백기의 사용 조건도 같다. 중앙선을 넘은 손까지 같은 사람에게 추적하는 방식은 이번 변경에 포함되지 않는다.

## 검증

- 전체 `npm test` 통과: 공통 11그룹, 떡방아 동작 검사, 화면·음성 22그룹, 장보기 9그룹, 손 인식 7그룹.
- 새 손 검사에서는 청기백기의 실제 프레임 루프와 두 게임 손 엔진에 전달되는 원본 영역을 비교했다. 역할 교대, 참가자별 독립 입력, 양손의 비동시 움직임, 한 손 누락, 캐시 오염 방지, 정지 영상, 부분 GPU 초기화 실패 시 정리와 CPU 전환을 검증했다.
- 화면 검사에서는 손 모델 초기화가 5초 늦어져도 떡방아 응답 시간과 장보기 120초가 유지되는 것을 확인했다.
- 타입 검사와 빌드 통과. 이전 브라우저 검사에서 얻은 공개 샘플의 실제 모델 관절을 회귀 검사에 사용했다. 새 플레이어 엔진의 카메라 입력은 모의 모델로 검증했으며, 수정 후 실제 모델·카메라 동시 실행은 확인하지 않았다.
- 브라우저 자동 점검은 도구 실행 환경의 `setup refresh had errors` 오류로 실행하지 못했다. 개발 서버는 실행했고 점검 페이지 HTTP 응답 및 Vite 모듈 변환을 확인했다.

## 현장 확인

`http://127.0.0.1:5200/docs/hand-recognition/`에서 카메라 검사 시작 후, 청기백기처럼 좌우에 서서 두 손을 자기 구역에 둔다. 장보기에서는 1P만 잼잼하고 2P는 손을 편 채 유지한 다음 반대로 검사한다. 해당 참가자의 횟수만 증가해야 한다. 떡방아는 왼쪽·오른쪽을 바꿔 각각 3회의 완전한 잼잼을 검사한다.

몸은 보이지만 손이 0~1개로 표시되면 손 검출 문제, 손이 2개인데 계속 움직이는 중이면 펼침/쥠 판정 문제, 몸이 안 보이면 Pose 존재 검사 문제로 구분할 수 있다. 실제 상태를 확인한 후 필요한 부분을 추가 조정한다.
